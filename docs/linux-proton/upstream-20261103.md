# OptiScaler upstream integration, 2026-11-03

Merge `optiscaler/master` at `ed5708bb` (9 commits after `e7e3872d`) onto Retoque
`fc4323a5`, on `integrate/upstream-20261103`. No submodule moves.

## Why now

- `e6a4c3e8`, `db646bcb`, `9302028e`, `df8a8f13`, `95fb9d0f` add the plugin API
  (`OptiScaler/plugins/PluginApi.*`, `plugin_sdk/`): an ASI plugin that exports the init entry point gets menu
  tabs, config access through `Config::GetRawValue`/`SetRawValue`/`SaveRawValues` (a new recursive `iniMutex` in
  `Config.cpp`) and, after `df8a8f13`, custom upscaler and FG DLLs may use it too.
- `6a7b0336` accepts any `SUCCEEDED` result (`DXGI_STATUS_OCCLUDED` for a fullscreen swapchain created while the
  window is not in the foreground) when wrapping swapchains in `DxgiFactory_Hooks.cpp`/`DxgiFactory_WrappedCalls.cpp`.
- `97e7e793` hooks `ID3D12Device::CreateComputePipelineState`: when creation fails and the DXIL requires native
  16-bit ops, the requirement is cleared from `SFI0`, the container is re-hashed and creation is retried (FSR4 on
  Pascal). `ab379b25` corrects RDNA1 INT8 checks; `2e8032de` drops a Control Resonant default.

## Conflicts and decisions

- `OptiScaler/OptiScaler.vcxproj`: both sides added headers at the same place; kept the fork's two
  `retoque/menu` telemetry headers and upstream's `plugins/PluginApi.h` and `plugin_sdk/optiscaler_plugin.h`.
- `OptiScaler/menu/menu_common.cpp`: the sidebar label. Upstream now draws a precomputed `label` clipped to the
  tab; the fork translated built-in labels with `Localization::Tr`. Resolved as upstream's drawing with
  `Localization::Tr` applied to built-in labels only; plugin tab names are drawn as the plugin gives them.
- Remaining `result == S_OK` checks in the two DXGI factory files are the adapter-enumeration ones, identical in
  count and place to upstream; the fork has no extra swapchain-creation site in those files.
- The new compute-pipeline hook only acts on a failed creation. NR's pipelines, including the keepless
  permutation (built only when `TypedUAVLoadAdditionalFormats` is reported, and not requiring native 16-bit ops),
  are unaffected: a failure is returned unchanged when the requirement is absent.
- The `iniMutex` guards the shared `CSimpleIniA` in every entry point that touches it (`Reload`, `LoadFromPath`,
  the overlay export/apply, `SaveIni`, `SaveXeFG` and the raw-value calls); the fork's NR reads and writes run
  inside those, and the NR settings mutex is taken within them without a reverse order. It does not protect the
  live `Config` fields read by render and menu threads; plugins reach only the raw-value calls.
