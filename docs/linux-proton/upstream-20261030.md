# OptiScaler upstream integration, 2026-10-30

Merge `optiscaler/master` at `e7e3872d` (4 commits after `e57377fc`) onto Retoque
`d5400e84`, on `integrate/upstream-20261030`. No submodule moves.

## Why now

- `941ce6a1` adds custom `nvngx_dlssg` replacements from `custom/<name>/dlssg`
  (`FGNvngxReplacement=<folder>`, new `Nvngx_Custom`, shared `Nvngx_DllProxy::LoadNgxExports`)
  and renames `upscalers/CustomUpscalers.h` to `misc/CustomProviders.h` (namespace
  `CustomProviders`).
- `b6f25bb7` adds Vulkan to the FFX nvngx FG replacement (dispatch only; no swapchain
  creation), exposes `FSRFG_Vk::GetLayout`/`IFGFeature_Vk::ImageBarrier`, and keeps the
  D3D12 FSR4 driver providers away from Vulkan FFX modules (`FfxApiProxy::IsVkModule`).
- `f81d9d20`/`e7e3872d` add the `ExtendedSearch` quirk (bounded `Plugins` search in
  `Util::FindFilePath`) for Phantom Blade Zero.

## Conflicts and decisions

- No textual conflicts. For all 27 upstream-touched files the fork's added/removed lines
  against `e57377fc` are identical before and after the merge, including the renamed header.
- `proxies/NVNGX_Proxy.h` changed only its include and namespace. The private
  `PFN_*_CoreShutdown1` types, `ShutdownDx11Device`/`ShutdownDx12Device`/`ShutdownVulkanDevice`
  adapters and the custom runtime's public-SDK `ShutdownCustomDx12` path are unchanged.
  `nr-shutdown` slice boundaries do not involve the renamed namespace; no test edits.
- Vulkan hooks, DLSS-G Vulkan, present host and NR code were not touched upstream.
  D3D12 internal-resource scopes in `FfxApi_Proxy.h` still cover the nvngx FFX route,
  which now calls those functions through a per-API table.
- The project files list `Nvngx_Custom.h/.cpp` and `misc/CustomProviders.h`.
