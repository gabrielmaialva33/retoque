# OptiScaler upstream integration, 2026-11-26

Merge `optiscaler/master` at `a1e0e193` (27 commits after `4a8d55a9`) onto Retoque
`3abf29b5`, on `integ/upstream-20261126`. Four files required manual conflict resolution;
no submodule moves. This record describes source integration and local validation,
not runtime qualification. The default branch and game installations are outside this task.

## What upstream brings

- Custom NGX runtimes can expose native D3D11 DLSS. Export discovery uses a mapped PE
  image without executing the provider; provider selection clears stale custom names,
  and the FPS overlay displays the selected custom provider's name.
- Vulkan FFX version queries receive device context and retry an early device-less query.
  DLSS-G extra queues prefer consecutive slots in one family; FG swapchain image queries
  clamp oversized output arrays to the actual count.
- DXVK factory/instance creation guards avoid recursive overlay loading. Agility SDK
  upgrades check that the runtime exists. XeLL creation propagates passthrough failure,
  partial XeFG contexts are destroyed, and XeLL follows the ReShade device layer.
- FG command objects replace an owned Streamline proxy with an owned real-object reference,
  retaining the real object before releasing the proxy. Existing GPU completion gates remain.
- OptiSharpen now has Natural/Crisp models, fp32/fp16 packed variants and separate precompiled
  pipelines per preset. Vulkan creates these pipelines lazily. The HDR limiter and optimized
  shaders arrive with their upstream bytecode; D3D11 uses fp32 for both precision selections.
- Enum serialization, DAS naming, FSR hook status, Flip Meter failure explanations,
  MacType notifications, Zhuxian defaults and the GPU identification database are updated.

### Conflict resolution

- `State.h`: keep `creatingVulkanInstance` as thread-local state; leave obsolete
  `vulkanSkipHooks` absent. The fork uses scoped per-thread hook suppression elsewhere.
- `menu_common.cpp`: external DLSS-G telemetry still supplies base FPS when available.
  Otherwise show measured base FPS only when `fg->IsGenerating()` or the upstream NGX
  generation-count condition says generation is active.
- `Nvngx_Proxy.h`: keep upstream `InitDx11Module` factoring for regular/custom runtimes,
  but both initialization signatures use `SdkVersion()` so an unset NGX version still
  gets the fork's API-version fallback.
- `DLSSFeature_Dx11.cpp`: retain both NR scene and ImGui notification includes. The
  successful runtime evaluation still calls `EvaluateNativeDx11Scene` before returning.

### Fork preservation checks

- `Streamline_Proxy.h` is byte-identical to the base: active plugin binding, bundled-hook
  fallback, MFG unlock and runtime remapping remain unchanged. The Proton DLSS-G provider
  redirect in `LibraryLoad_Hooks.cpp` remains alongside the incoming loader changes.
- `Vulkan_Spoofing.{h,cpp}` and `DlssNr_VkExtensions.h` are byte-identical to the base.
  The NR creation hook still uses `RealEnumerateDeviceExtensionProperties`, not a function
  obtained from a captured `VkInstance`; `210bff4e` and its stale-instance test remain.
- Fork destruction routing, device-owner retirement, failed-drain abandonment, NR hooks,
  frame-generation completion gates and the Linux overlay remain. No fork shader or NR
  constant buffer changed. The only fork-owned production edit is the profile enum call.
- All 28 incoming retained shader source/header/binary files are byte-identical to
  `a1e0e193`; generated headers were not formatted or regenerated locally. No new model
  DLL is included. The app schema and UI are unchanged.

## Sharpening versus DLSS-NR

The [previous integration record](upstream-20261119.md#sharpening-versus-dlss-nr) describes
ordering, which is unchanged: internal D3D12/Vulkan after-upscale NR sees sharpened output;
a successful NR pre-upscale route runs before sharpening; admitted native D3D11 scene NR
runs inside DLSS evaluate before sharpening; native DLSS passthrough bypasses OptiScaler's
sharpening pipeline. Present NR sees the later frame. NR comparison restores the input it
received, including upstream sharpening where applicable.

Unlike the previous batch, Vulkan OptiSharpen pipelines are now lazy and per variant.
They are captured by value into the existing owner-scoped deferred-release queue during
teardown. D3D12 retains deferred releases; D3D11 runs the two fp32 pipelines. Source review
and host tests do not measure the new shaders' cost or qualify GPU lifetimes in a game.
