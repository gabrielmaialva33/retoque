## Resource lifetime changes in `73deae91`

This commit is accepted as requested. It changes more than allocation sizes:

- `DeferredRelease` clears the live pointer immediately and queues destruction.
  Collection runs after eight hooked presents **and** 500 ms, or after two seconds
  without enough presents, when `Process`/`Collect` next runs. This is an age/count
  heuristic, not a GPU fence or a guarantee that all consumers have finished.
- D3D12 shader pipeline/root signature/constant buffer destruction, replacement
  output buffers and derived shader buffers now defer release. Shader outputs use
  only requested flags, one mip, default layout/alignment, and a default heap when
  source heap properties cannot be read. Depth scaling uses source-sized resources.
- FG resource copies are cleared when disabled or contexts are destroyed; their map
  entries remain while pointers are nulled. FSRFG adds a callback-resource mutex,
  releases it before SDK/LSFG dispatch, collapses per-slot HUD helper instances, and
  frees its transfer/reprojection helpers while disabled. XeFG, DLSS-G and the
  reprojection output invoke copy cleanup on their respective disabled paths.
- HUD capture removal replaces its prior per-batch completion fences with the same
  deferred queue. HUD buffers/helpers and depth-scale input helpers are released
  when unused. FSR3/FfxApi input buffers and NGX DLSS-G depth copies also enter that
  queue on replacement, context destruction or disabling the relevant option.
- Vulkan shader objects, image copies and Vk/D3D12 bridge replacements enqueue
  device-owned image views/images/memory rather than freeing immediately. New Vulkan
  device creation drops queued callbacks belonging to other owners without invoking
  them; shutdown abandons entries. FSRFG Vulkan can reuse an existing own HUDless copy.
- DXGI and native Vulkan presents process the queue (DXGI-backed Vulkan avoids a
  second count); evaluation paths collect aged entries when presents are unhooked.

Our D3D12 menu completion tickets, retained queue and allocator/cleanup waits remain
unchanged. Vulkan menu drains and cross-family fence/semaphore chains remain in place.
The new callback-resource mutex has its own scope, nested outside per-frame resource
cleanup; it does not replace the swapchain's scope-owned FG mutex. Those protections
do not prove the safety of upstream's age-based release queue under a long GPU stall,
multiple devices, or an SDK's private queues. Do not infer lower VRAM usage or safe
GPU lifetime merely from compilation or host tests.

## NR device-teardown integration fix

Independent review found a concrete new regression: `Shader_Vk` now enqueues callbacks
that capture a `VkDevice`, while the NR host previously released its passes immediately
before destroying that device. An already existing second device could later collect
those callbacks. Dropping other owners at device creation alone cannot prevent it.

The follow-up preserves `73deae91` and adds owner retirement at the NR device boundary.
`RetireOwner` serializes against collection **including callbacks already detached**
from the pending vector. After the existing bounded teardown proves all work idle,
it destroys queued resources before the device; loss, an incomplete drain or leaked
work instead abandons them. A retired owner refuses late enqueues. Successful device
creation reopens a reused numeric handle with `RegisterOwner`. The retirement runs
outside the host's transport/registry/queue locks, before the downstream device destroy.
The ordinary age/present heuristic is retained, with its limitations above.

`deferred-release` reproduces the old dead-device callback and tests the production
queue under a fake clock, including a barrier-controlled detached-collector race.
Three mutation controls reject lost-owner destruction, late enqueues and unsynchronized
retirement. FG teardown ordering and all three FFX signature names also gain checks.

## Verification boundaries

The untouched base passed 59 host suites. The new owner-retirement suite brings the host registry to 60. The first merged run exposed three fixture
adaptations: FSR4's provider rename, the new Vulkan timeline timing API, and an LSFG
source guard that assumed the old adjacency of state clearing and teardown. Update
the fixtures to the new APIs/order, keeping the production slices and assertions.
The Wine HDR fixture links the new production deferred-release dependency. The timing
fixture discovers an installed Proton rather than hardcoding a removed version. Two
Wine suites acquire the same MSVC lock internally; nesting the requested outer flock
makes them refuse execution, so their final runs use their own lock serially.

The timer suite additionally exercises the interop slot state machine with scripted
counter/query replies, including pending, failed, unavailable and quarantined slots.

Final build, host/wine counts and artifact hashes are recorded in the accompanying
local JSON report. The Vulkan overlay fixture builds an instrumented DLL separately;
its result must not be confused with a production-DLL run. Host tests use fakes and
do not establish real SDK output, GPU safety, image quality or performance.

In-game paths remain unvalidated: Crimson Desert (NR after upscale + DLSS-G),
Divinity (D3D11 bridge + NR + synthesized FG), DOOM Eternal (Vulkan NR + menu), and
PCSX2 (D3D12 present pass). Native Windows/D3D12 validation, AMD/FSR4 behavior and real
XeFG Dynamic MFG/reprojection quality and pacing also require separate validation.
