## Lock and teardown ownership

These are the integration's ordering constraints, not a proof about arbitrary vendor callbacks:

| Operation | Order / ownership | Completion or refusal |
|---|---|---|
| Deferred collection/retirement | recursive execution mutex, then queue mutex; invoke callbacks after releasing queue mutex | Retirement drains nested batches with execution ownership, or drops them without invocation after a failed drain. Retired owners reject later enqueue; registration serializes before reuse. |
| Vulkan device registration | RegisterOwner completes before acquiring hooked-device registry mutex | Creating another device never drops the existing live device's callbacks. |
| NR device preparation | HostActivity, then TransportLock for model/transport teardown; trace and registry locks in separate later scopes | Returns tracked-success, tracked-failure or untracked. Deferred retirement occurs outside transport/registry locks. |
| Bundle vkDestroyDevice | NR preparation, overlay release, deferred retirement, hooked-device erase, then real destroy | Only untracked NR permits driver-idle fallback. Explicit false is never promoted. A second hook sees the retirement tombstone and cannot run callbacks twice. |
| Vulkan menu lifecycle | present mutex, then clean mutex consistently | ReleaseDevice filters identity and abandons on failed drain; old swapchain filtering is preserved. No new inverse try-lock policy. |
| FG resize/fullscreen | ResizeScope holds the acquired feature's OwnedMutex; nested/current-thread and owner7 window-message cases avoid reacquisition | Guards remain tied to the original instance if currentFG changes. Successful resize precedes publishing its queue. |
| FG swapchain release | resize fence mutex serializes signal/wait; provider release follows completion proof | Missing/failed/lost/stale completion refuses teardown; synth release follows proof. Only owned provider references are released. |

## NGX baseline regression

The first trial DLL crashed inside the native NGX core on the first DLSS CreateFeature. The same
loopback executable, GPU, driver, core, SR/NR model and Streamline payload passed with the pre-upstream
baseline; replacing only the trial DLL/its matching forwarder reproduced the crash. This was treated as
an integration blocker, not an environment limitation.

The incoming AllocateParameters guard required successful API init. When the game's initial native init
returned FAIL_OutOfDate, it bypassed the available core allocator and returned an internal parameter table.
A later lazy init succeeded and selected native DLSS, which received that internal table and crashed.
The baseline still attempted core allocation before successful feature init. The integration restores that
contract for D3D11, D3D12 and Vulkan, keeping the loaded-module/function checks, null-output rejection and
fallback after actual allocator refusal. GetParameters/GetCapabilityParameters retain their own init gates.

`tests/fork-compat/parameter_cases.py` compiles the three production allocation entry points: all three
failed before restoring the contract and pass afterward, including missing/disabled/refusing allocator cases.
After rebuilding, the real D3D12 loopback selected native DLSS successfully and completed five creates,
3,661 evaluates, three NR compositions and successful shutdown. This does not qualify every native core version.
