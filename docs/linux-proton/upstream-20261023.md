# OptiScaler upstream integration, 2026-10-23

Merge `optiscaler/master` at `83e18f1a` (38 commits after `c2e44a8b`) onto Retoque
`fa5888fb`, on `merge/optiscaler-20261023`. Integration into `dlss-neural-rendering`
waits for the validation below.

## Why now

Four upstream commits fix things this fork has:

- `83e18f1a`: a deadlock at Cyberpunk 2077's launch. `LibraryLoad_Hooks.cpp` held the
  Streamline mutexes across `LoadLibraryExW_Ldr`, the pattern the commit removes.
- `8f0b7d87`: XeFG in Cyberpunk 2077 picking up the game's older XeLL.
- `d06f31e9`: the D3D12 menu indexed an eight-entry back-buffer array with the swapchain's
  index, past the end with XeFG at 6X or any chain of more than eight buffers.
- `c4668477` (#1161): the device extension list is read from the device's real list,
  each name once, KHR and EXT buffer_device_address never together, and the extensions
  OptiScaler only pretends to offer are filtered out when DXVK/vkd3d-proton creates a
  device. This is the fix janblade carried as `019ab55a`.

## Upstream behaviour taken, and explicit decisions

- `5dfedd68` removes fakenvapi's low-latency implementation. `ReflexHooks::update` loses
  its `lastLowLatencyMode` static and the commented block that waited for fakenvapi. Our
  `cd31c126` (clear the driver's limit when pacing falls back to FrameLimit) is kept:
  its statics stay at the top of the function. `fakenvapi::isUsingAsMainNvapi`, which the
  NR module's NGX report reads, still exists.
- `a79c2f34` removes the non-low-latency paths, `LOW_LATENCY_INPUTS` and
  `fgPresentIsCalled`. The DLSS-NR present hook in `FG_Hooks.cpp` stays where it was,
  before the original present; only the `fgPresentIsCalled` write and the `#ifdef`
  around the low-latency code go.
- `1b96d168` requests `DXGI_SWAP_CHAIN_FLAG_FRAME_LATENCY_WAITABLE_OBJECT` for the DLSS-G
  swapchain only under the new `GameQuirk::DLSSGFrameLatencyWaitable` (Kingdom Come:
  Deliverance II). **Kept ours: the flag for every title** (`f06178df`, `380388e8`).
  It is what disarms sl.dlss_g's flip-queue throttle on Ada, measured here as a 20-30 fps
  menu and MFG output capped at 2x without it. The quirk stays defined and is subsumed.
- `c4668477` restructures `hkvkCreateDevice`: feature state, spoofing with the requested
  API version, and the create call in one scope. The NR device-extension block moves into
  that scope, after spoofing and before `o_vkCreateDevice`, with upstream's
  `localCreateInfo` spelling. Spoofing now adds `VK_NVX_binary_import`,
  `VK_NVX_image_view_handle` and `VK_KHR_push_descriptor` itself wherever the device has
  them, so the NR block mostly reports them as already present; it still adds the KHR
  buffer_device_address the model names, and its EXT/KHR conflict rule stays.
  Every `State::vulkanSkipHooks` read upstream added becomes our per-thread
  `ScopedSkipVulkanHooks::Active()` (the hooks, the low-latency proc hook, the new
  RADV cooperative-matrix instance step).
- `b543eb15`: the Vulkan menu remembers the swapchain it was made for and presents any
  other without the menu; `CreateSwapchain` returns before anything when the menu lives on
  another window. The window check runs before our locks and drain, so a second window's
  swapchain can no longer tear down the menu's objects; the swapchain check runs after
  our locks, where `_menuSwapchain` is written.
- `737a21d5` (several Vk w/Dx12 upscalers): fence-only submits pass straight through.
  The per-`VkQueue` recursive lock is kept ahead of that check.
- `76219dd4`, `c220ad9e` (menu): upstream's tab table (no descriptions, separators instead
  of group headers, `Latency`, `Status`) plus our `Neural Rendering` tab after Upscaling.
  Card titles are translated inside `ScopedCard::DrawTitle`, so the first-heading titles
  `TryTitle` draws are translated too; Save/Close, the wiki tooltip and the renamed FSR FG
  header go through `Localization`. The window title keeps the `Retoque | ` prefix with
  upstream's fixed `###OptiScalerMenu` ID.
- `0d795d6c`/`6cce5d7c` (ours) are subsumed by upstream's own rewrite of
  `TranslateTypelessFormats` in `Shader_Dx12.cpp`: the typeless depth plane is no longer
  translated to the depth-stencil format, and the typed depth formats map to their SRV
  planes. Upstream's text taken whole.
- `b686ef4b` splits the FSR4 driver provider into `FSR4DriverProviderDx12` and
  `FSR4DriverProviderVk`. The renames are taken; `Crypt32_Hooks.h` keeps our
  `amd_fidelityfx_upscaler_vk.dll` signature redirect (`de0499a8`), the one part of that
  commit upstream did not adopt, and `FfxApi_Proxy.h` keeps `ScopedInternalResourceCreation`.

## Follow-ups on the branch

Codex reviewed the merge on 2026-10-23 (`~/.cache/retoque-wt/codex-discussion-20261023.md`,
local). Each finding below was checked against the code before it was acted on.

- `43d842f8`: the NR block does not append `VK_KHR_push_descriptor` behind a
  `VkPhysicalDeviceVulkan14Features` whose `pushDescriptor` is off (the rule the present
  host's plan already applies, and upstream's spoofing now applies to its own append).
  Pinned in `nr-vk-extensions`.
- `d391a944` (review A-01, from upstream): the spoofing's extension lists are
  `static thread_local`. The new DXVK/vkd3d-proton branch added a third function-static
  list whose `data()` the caller hands to the driver after the spoofing returns; a create
  on another thread could rewrite it in between. Needs `VulkanExtensionSpoofing=true`.
- `e35f1c76` (from upstream): `vulkanMemoryModelDeviceScope` is enabled wherever #1161
  enables `vulkanMemoryModel`. Without it FSR 2.2's Device-scope atomics failed
  `vkCreateShaderModule` validation in `nr-route-*-wdx12`.
- `68b5a0e5` (ours, older than the merge): the Vulkan menu's render area is the swapchain
  extent, not ImGui's `DisplaySize`, which the Win32 backend takes from the client area each
  frame. A window resized before its swapchain is recreated broke
  VUID-VkRenderPassBeginInfo-pNext-02852/02853; Hyprland tiling the test windows exposed it
  with the pre-merge DLL too.
- `29e9049a` merges `codex/nr-fixes-20261023`, Codex's fixes for its other findings, which
  predate the merge:
  - `c397eb1d` (A-02): the DLSS-G resize hooks keep the frame-latency waitable bit of the
    chain as created (`GetDesc`), so a resize never adds or removes it; DXGI refuses that.
    Our creation adds the bit for every title since `f06178df`, and the hooks kept only
    `ALLOW_TEARING`. `fg-resize-flags`.
  - `47d53f6b` (B-01): a readable guide clone is retired when any part of CopyResource's
    shape changes (mips, slices, samples, dimension), not only its extent.
    `nr-guide-copy-contract`.
  - `80a1ab0f`, `77495b8b`: the MFG clamp limits the count sent to the provider and never
    overwrites the saved `OverrideInterpolationCount`; the provider's maximum is re-read per
    provider generation (a module loaded or patched) instead of latched on the first read,
    and the stable per-frame path is two atomic loads. `mfg-provider-capacity`.
- Fixtures: `fork-compat` (provider rename), `nr-localization` (the new tab table),
  pt-BR entries for the renamed and new menu text, `repo-privacy`'s home paths in the lease
  guard cases (failing on `dlss-neural-rendering` since `42459482`), and
  `vulkan-present-host` (`541184b9`): beside the bundle, upstream's spoofing now appends the
  model's extensions and turns on bufferDeviceAddress and
  shaderStorageImageWriteWithoutFormat itself; and the wDx12 probe, which relied on the hook
  rejecting a Vulkan-valid zero-batch submit, now requires that call to succeed and takes
  the hook's attach line from the log.
