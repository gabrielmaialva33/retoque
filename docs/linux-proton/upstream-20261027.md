# OptiScaler upstream integration, 2026-10-27

Merge `optiscaler/master` at `b19cfd29` (16 commits after `12fd52d8`) onto Retoque
`15f8892f`, on `merge/optiscaler-20261027`. No submodule moved.

## Why now

- `54f310f7` (Path of Exile 2, V-Sync switch on Vulkan): `hkvkCreateInstance` and
  `hkvkCreateDevice` no longer take an instance or device created inside a D3D device's
  creation (`State::creatingD3DDevice`) as the game's, and the Vulkan menu is no longer
  handed it. The flag is set around OptiScaler's own D3D devices (GPU identification, FFX,
  the NR pair capture, the D3D12 hooks' probes); under Proton those go through DXVK or
  vkd3d-proton, so each of them creates a Vulkan instance and device in the game's process
  that the hooks used to capture. `HookDevice` still runs on every device.
- `c2876a76` (#1237): the game's own FSR frame generation keeps its swapchain (Modern
  Warfare 4 crashed when XeFG took it), AntiLag 2 frame types by position in XeFG's batch,
  and Dynamic MFG ignores an isolated hitch and keeps its count in the background.
- `808e5c5e`: `slSetFeatureLoaded` is resolved with the other DLSS-G entry points, so the
  DLSSG input's hook goes in (Doom: The Dark Ages greyed out its frame generation).
- `d023e06e`: OptiScaler's FPS limit with DLSS-G on Vulkan counts presented frames.
- The FPS overlay rework (#1238 and `5f6a2e69`, `3c6263ec`, `7937e473`), `8feb5d0c` (FSR-FG
  version switching while FG is off), `539c9a1e`/`b19cfd29` (FFX on Vulkan), `a6b87315`
  (validation-layer fixes) and `fd3a45a6` (the .asi version in the menu).

## Conflicts and decisions

- `framegen/xefg/XeFG_Dx12.cpp`: `c2876a76` moves Dynamic MFG into
  `XeFG_DynamicMFG.cpp`, taking `DisplayRefreshFps` and `DynamicTargetFps` with it. Upstream's
  `XeFG_DynamicMFG::TargetFps` is the old target without our V-Sync rule (`03e7fda3`): it
  still lets an explicit target or FPS cap sit above the refresh rate while frame generation
  presents with V-Sync. **Kept ours**: `TargetFps` now returns `XeFG_DynamicTargetFps(...)`
  with `State::fgPresentVsync`, the same pure function as before. `tests/xefg-dynamic-target`
  slices `XeFG_DynamicMFG::TargetFps` instead of `XeFG_Dx12::DynamicTargetFps`.
- `menu/menu_overlay_vk.cpp`: `a6b87315` checks the result of an unbounded
  `vkWaitForFences` on the frame fence. **Kept ours**: that wait was replaced by a bounded
  one with its own result check (`10c6760`), further down the same function. The other
  hunk of `a6b87315` in this file (the debug name of the back-buffer semaphore) merged.
- `menu/menu_common.cpp`:
  - The overlay rework replaces the line builder that carried our external DLSS-G telemetry
    (a game's own DLSS-G seen through `DlssgExternalTelemetry`). It is re-applied on
    upstream's structure: `fgText` gains "DLSSG source telemetry", and the FPS value shows the
    telemetry's base frame rate.
  - `Shutdown` takes upstream's overlay font reset and keeps our `std::atomic_ref` stores
    (`8feb116f`).
- The overlay's four new section titles (Presets, Layout, Text, Colors) got pt-BR entries;
  `nr-localization` fails on any label without one.

## Verification boundaries

Host tier, the Release build and the wine suites listed in the merge commit. Not covered:
the reworked overlay, AntiLag 2 and XeFG Dynamic MFG in a game (no AMD or Intel output
here), and `54f310f7` in a D3D12 title with the Vulkan hooks left on.
