the existing sharpness/MAS eligibility, resources and motion-vector checks still apply.
On D3D11/D3D12 the OptiSharpen pipeline is created lazily when selected. Vulkan creates
it in the RCAS constructor alongside the other sharpening pipelines, even with RCAS
selected and NR off. That additional initialization work is upstream behavior; no
runtime cost is measured here. Its destruction uses the existing deferred-release queue.
The overlay's model/debug controls are inside the OptiSharpen method branch; both edit
their own key and reset those two keys. NR's controls and constants are unchanged.

## Sharpening versus DLSS-NR

These are source-order observations, not image-quality measurements.

- **Internal D3D12, after upscale / Upscaled hook:**
  `IFeature_Dx12::Evaluate` evaluates the backend, then dispatches its post-processing
  pipeline forwards, including `RCAS->Dispatch` (which selects OptiSharpen).
  `NVNGX_DLSS_Dx12.cpp` calls `EvaluateAfterUpscale` only after that evaluate returns.
  Thus, when sharpening runs successfully, NR reads the already-sharpened output.
  The fork's deferred legacy menu is rendered after NR.
- **Native Vulkan:** `IFeature_Vk::Evaluate` similarly finishes the sharpening pipeline
  before `NVNGX_DLSS_Vk.cpp` offers the result to `EvaluateAfterPreSafeVk`.
  D3D11-on-D3D12 and Vulkan-on-D3D12 bridges call the D3D12 feature's evaluate before
  their NR after-pass; the Vulkan caller excludes these bridged backends from a second NR pass.
- **Before upscale (`Stage=1`):** the pre-upscale scope runs before the backend and its
  sharpening. If it succeeds, the after-pass stands down. A declined pre-upscale route
  can fall back to the after-pass and therefore see sharpened output.
- **Native DLSS passthrough:** the NGX passthrough branch calls the native DLSS evaluator
  directly, then offers its output to NR. It bypasses `IFeature_*::Evaluate` and the
  OptiScaler RCAS/OptiSharpen pipeline. This branch does not add OptiSharpen; any native
  DLSS/game sharpening is separate.
- **Native D3D11 scene-stage experiment:** when its opt-in admission succeeds,
  `DLSSFeatureDx11::EvaluateInternal` calls `EvaluateNativeDx11Scene` immediately after
  native DLSS, inside the outer feature's evaluate. `IFeature_Dx11::Evaluate` dispatches
  RCAS/OptiSharpen afterwards. Here the order is DLSS → NR → sharpening, unlike the
  D3D12 bridge. Ordinary native D3D11 does not acquire this scene-stage NR by selecting
  a sharpening shader.
- **NR passthrough/comparison:** `gPassthrough` describes display-referred color encoding,
  not bypassing upstream sharpening. `ApplyModel=0` and the untouched comparison side
  restore/show `originalSample`, the frame NR received. On a sharpened internal route
  that original is already sharpened; these controls do not undo OptiSharpen.
- **Present placement:** NR reads the later presented image, including any sharpening
  that actually reached that frame. Present-only applications do not gain an
  OptiScaler upscaler/sharpening pass merely by enabling NR.
