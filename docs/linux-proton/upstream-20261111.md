# OptiScaler upstream integration, 2026-11-11

Merge `optiscaler/master` at `559fca7e` (31 commits after `34d492d6`, 2026-11-09 to 11-11) onto Retoque `2dd32d31`,
on `integrate/upstream-20261111`. Four files conflicted; no submodule moves.

## What upstream brings

- Menu input: the bit "pressed since the last call" that Opti's own `GetAsyncKeyState` polling takes is handed back to
  the game (`WithTakenAsyncKeyPress`); DirectInput keeps owed key and button releases instead of flushing them while
  blocked, filters only the events the menu had, reports a centred joystick while blocked, and calls the originals
  through per-slot hooks (devices created before the hooks are hooked too); every loaded XInput DLL is hooked; raw
  input buffers are walked with their alignment; each subclassed window forwards to its own original WndProc.
- Custom DLSSD: a custom ray reconstruction DLL (`Nvngx_RR`, `proxies/Nvngx_RRDllProxy`) beside the custom DLSS-G one.
  The NGX DLL proxies move to `proxies/` and load their exports through one shared `NgxExports` base;
  `proxies/NVNGX_Proxy.h` is now `proxies/Nvngx_Proxy.h`.
- FG: stop FG when the game turns DLSSG off and untags its inputs (`Streamline_Inputs::reportGameMode`); keep stopping
  FG on the game's swapchain without the overlay menu; do not tear the menu down from other windows' swapchains.
- Loading: with `LoadReShade`, ReShade hooks the DXGI factory before Opti (ReShade above the FG swapchain used freed
  objects); ASI plugins load in `DllMain` again; device creations no longer race the GPU detection's amdxc64 leak fix.
- `EnableCOMDATFolding` is off in Release, so hooked stubs never share code; FSR 4 stays off on non-AMD GPUs unless
  `Fsr4GpuSupport` enables it; Anti-Lag 2's proxy gets the device it initializes with.

## Decisions

- `Nvngx_Proxy.h`: upstream's structure (`NgxExports`, `NgxFeatureModule`, `NvngxModule::LoadExports`) is taken. The
  fork's layer is reapplied on it: the runtime's `Shutdown1` slots keep the two-argument core type
  (`PFN_*_CoreShutdown1`, which replaces upstream's equivalent `PFN_Nvngx_*_Shutdown1`), the public getters still
  return the one-argument adapters (`ShutdownDx12Device`, `ShutdownDx11Device`, `ShutdownVulkanDevice`),
  `_dx12Shutdowns`, `SdkVersion()` at every init, the NGX log filter, and `DestroyParameters` without the init gate.
  The custom DLSSD module (`NgxFeatureModule`) keeps upstream's one-argument SDK `Shutdown1`.
- DirectInput: KcdInputFix keeps its hooks. Missed presses are appended to `GetDeviceData` only while the game itself is
  reading (on both of upstream's non-blocked returns, before the buttons are tracked), and to `GetDeviceState`'s
  keyboard state as before; nothing is injected while the menu has input.
- `RealGetAsyncKeyStateSafe`: the fork reads keys through `win32u!NtUserGetAsyncKeyState` beneath other overlays'
  detours. That is the same call user32 makes, so it takes the game's pressed bit too: the native read now records the
  bit like upstream's user32 read, and the game gets it back once.
- The `LoadReShade` factory order does not affect NR with ReShade: `ResTrack_Dx12::NrRealObject` unwraps Streamline's
  and ReShade's proxies in either order.
- Every include of the old header name in `retoque/` and the tests moves to `proxies/Nvngx_Proxy.h`.

## Tests changed

- `nr-shutdown`: slices the loader lines from `NvngxModule::LoadExports` and the two Vulkan shutdown slots from their
  new structs; fakes `Nvngx_RR`, which the SDK Vulkan shutdowns now also call.
- `mfg-provider-capacity`: the fake `State` gains `slFGInputs.reportGameMode`.
- `menu-native-key-state`: also splices `asyncKeyPressTaken` and `WithTakenAsyncKeyPress`; a native read's press bit
  is handed back to the game once.
