# OptiScaler upstream integration, 2026-10-29

Merge `optiscaler/master` at `e57377fc` (8 commits after `b19cfd29`) onto Retoque
`c5e32401`, on `merge/optiscaler-20261029`. FidelityFX-SDK-v2 moves from
`60f4ea81` (SDK 2.3) to `7539ae8b` (SDK 2.4).

## Why now

- `de2626f1` adds custom upscaler DLL folders for D3D12 FFX and DLSS;
  `63463bde` extends this to native Vulkan FFX. `760ae412` fixes context handling
  for custom FFX upscalers. Custom choices and their FFX version indices round-trip
  through the ini, separately from the regular backend.
- `a0161cd9` moves to FidelityFX SDK 2.4 and its separate Vulkan loader, upscaler
  and frame-generation modules. `6febb35b` keeps the legacy SDK DLL fallback
  when a newer per-feature DLL is absent. Vulkan inputs translate the backend
  descriptors for SDK 1.x and 2.x.
- `fe2fa45e` forwards XeSS's maximum responsive-mask value; `c4ff141c` hides FSR4
  from BeamNG's reported FFX versions.
- `e57377fc` removes upstream's stack-based detection/refusal of a game's FSR-FG
  swapchain under XeFG, introduced in the eighth merge. This is upstream's new
  policy, not a retirement of a fork-owned patch.

## Conflicts and decisions

- `proxies/NVNGX_Proxy.h` was the only textual conflict. Kept upstream's
  `CustomNgxModule`, function-table factoring and shared `InitDx12Module`, with
  the fork's fixes reapplied:
  - The shared initializer calls `SdkVersion()` on both project-ID and application-ID
    routes, preserving the nonzero fallback before a game has initialized NGX (`d6ac00f6`).
    D3D11 and Vulkan keep their existing fallback too.
  - Driver-core `Shutdown1` retains its two-argument type, writable remaining-count
    output and null-device adapter (`0d9860fb`). The common export loader does not
    assign that ABI: the normal core resolves it separately, and custom modules
    have a separate one-argument SDK pointer, as upstream's custom route expects.
    The custom pointer is never handed to the core adapter. `nr-shutdown` now
    compiles and exercises both production shutdown paths with strict host fakes.
  - NGX failure logging and repeat filtering (`acc20074`, `c17a2d0f`), and the
    D3D12 shutdown-generation counter used by Transfer 2 (`0548fc80`), remain.
- Reviewed the automatic merges in `LibraryLoad_Hooks.cpp`, `Vulkan_Hooks.cpp`,
  `FG_Hooks.cpp`, `FfxApi_Proxy.h`, `FfxApi_Vk.cpp`, `menu_common.cpp`, `dllmain.cpp`,
  `Config.h/.cpp`, `OptiScaler.ini` and the project files. Their fork-added/removed
  lines match the pre-merge fork delta against `b19cfd29`; only the NGX proxy
  needs a changed fork delta. In particular:
  - Thread-scoped Vulkan guards, owned device requests, NR extension/present hooks,
    device-lifetime handling and surface-window teardown guards survive.
  - MFG early loading, explicit NvapiPath, Streamline's own-interposer exclusion,
    FG fullscreen rules, DLSS-G back-buffer indexing and V-Sync targeting survive.
  - Internal-resource scopes in the normal FFX D3D12 create/configure/dispatch paths,
    external DLSS-G telemetry, atomic menu stores and NR menu/config wiring survive.
- No duplicate ini keys were introduced. `nr-localization` accepts the merged menu
  without new pt-BR entries; the new status tags are technical labels and custom
  display names come from folder names.
- Submodules are real directories, not symlinks. The seven small reference checkouts
  were shallow, which Git rejects as `--reference` sources, so those were initialized
  independently with `--depth 1` at their pinned commits. SDK-v2 used the main
  checkout as an object reference and checked out `7539ae8b`. The 13 legacy SDK
  header files were copied at their existing paths; it remains intentionally partial.
  The main checkout's submodule working trees were not updated.
- The project gained two headers (`CustomUpscalers.h`, `FfxModule.h`), and the SDK
  headers changed. The Release build starts from an empty worktree output directory
  with `/t:Rebuild`, so no older precompiled header is reused.
