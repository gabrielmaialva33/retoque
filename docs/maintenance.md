# Maintenance runbook

Current operating rules live here and in [CLAUDE.md](../CLAUDE.md). The full previous guide is preserved as
[historical notes](history/maintainer-notes-20261029.md); its dated measurements and patch decisions remain useful,
but installed versions and old pending steps must be rechecked.

## Build and toolchains

The product is a Windows x64 DLL plus forwarder, built from `OptiScaler.sln` with MSVC. Linux builds use
`tools/build-local.sh` / `tools/build_local.py` and MSVC under Wine. The root `build-local.sh` is a stable wrapper.

```bash
./build-local.sh Release
./build-local.sh Debug
./build-local.sh Release /t:Rebuild
```

The supervisor takes the shared compiler-prefix lock before stamps/builds; busy returns 75. Do not add another
lock around this entry, use MSBuild `/m` under Wine, or run fixtures against the compiler prefix concurrently.
Native Windows MSBuild may use `/m`. `MSVC_BIN` and `WINEPREFIX` can override local toolchain locations.

The supervisor separates forwarder/DLL stages, observes owned process identities and keeps invocation logs under
`x64/logs/`. Workload CPU/log growth, not wineserver CPU alone, counts as progress. A stall/deadline returns 124
with bounded cleanup. Never reset the shared prefix or kill unrelated processes as automatic recovery.
The historical stall investigation disproved several simple parallelism explanations; do not repeat them as fixes.

Redirect build logs to a file, never pipe a build through `tail`: daemonized Wine processes can keep a pipe open.
Both outputs must be successfully produced before deployment; output-pair replacement is not crash-atomic.
See the [build lifecycle](../tests/build-lifecycle/README.md) and [tool details](../tools/README.md#build-localsh).

## Submodules

Keep `fetch.recurseSubmodules=no`. Do not blindly initialize all submodules recursively. The legacy
`external/FidelityFX-SDK` intentionally has only required headers in this workstation's setup; the v2 SDK is
separate. Host CI needs only:

```bash
git submodule update --init external/simpleini external/spdlog external/vulkan
```

Follow the relevant build/merge record for a DLL build's complete prerequisites. A worktree is not automatically
populated from another worktree's submodules. When Vulkan headers change, use a clean rebuild rather than trusting
an incremental PCH, and regenerate/check `Vulkan_DeviceCreateChainTypes.h` with its generator.

## Formatting and shaders

Use clang-format 22 (`uvx --from 'clang-format==22.*' clang-format` where available). Match CI; do not silently
use a newer system formatter. Generated bytecode is excluded by `.clang-format-ignore`.
Every `.cpp` starts with `pch.h`; no header includes it. Stable system/third-party headers alone belong in the PCH.

HLSL and committed DXIL/SPIR-V headers are a pair. The shared NR shader requires both DX12 `cs_6_0` and Vulkan
`-spirv -D VK_MODE` rebuilds. NR and synth-motion live under `retoque/`, while shader tools remain upstream under
`OptiScaler/shaders/shader_tools/`. Use the [module recipe](../retoque/dlssnr/README.md) and verify constant layout,
passthrough and default-off behavior. Do not treat a newer timestamp alone as proof of correct shader behavior.

## Validation route matrix

| Route / failure class | Representative target | What a run must establish |
|---|---|---|
| D3D12 upscale + FG | Crimson Desert / Cyberpunk | Effective NR route, guides, frame boundary, completion and FG behavior |
| D3D11 bridge | Divinity / The Witcher 3 DX11 | Correct proxy/bridge, model admission and ownership |
| Native D3D11 DLSS guides | Sons Of The Forest | Depth/motion actually transported and selected, not merely detected |
| Vulkan | DOOM Eternal | Present-family transfers, menu, NR ownership and route hand-back |
| No-upscaler present | PCSX2 D3D12 | Present path actually runs and returns the correct frame |
| Windows-native D3D12 | A target Windows GPU | Descriptor/resource rules, device-removal diagnosis and actual loaded binary |

This is a test plan, not a claim that today's build passed. Use [capabilities](capabilities.md) for linked records.
Host tests, fixture GPU runs and game runs answer different questions. For source-only changes run the host tier;
for rendering changes also follow [DEVELOPMENT.md](dlssnr/design/DEVELOPMENT.md) and relevant runtime fixtures.

## Deployment and diagnostics

Use the receipt-aware installers with preview/uninstall support. Never write a proxy DLL mapped by a running game.
A second-copy pass-through guard does not make duplicate proxies a supported installation layout.
Edit existing INI keys in place: the parser keeps the last duplicate. Preserve user choices and install receipts.

The loaded proxy is identified by `CheckWorkingMode OptiScaler working as`; the menu's build stamp and binary hash
identify what actually ran. Model messages are in `OptiScaler.log`; NGX debug diagnostics may require `LogLevel=1`.
Do not overwrite Proton-managed system32 files to fix NVAPI: use the documented library-path/profile mechanism.

## Evidence and local research

Reference clones, user DLLs and raw captures stay ignored/local. Keep a small record of repository/revision,
model/driver, commands, settings, evidence identity and conclusions. Preserve failed/rejected experiments.
Do not publish personal paths or network addresses. Local temporary-folder aliases are not automatically
independent copies; inspect before cleanup and never remove another agent's artifacts.

Release qualification follows [VALIDATION.md](releases/VALIDATION.md). A dirty checkout or partial source test
run cannot become the CI release gate; a clean host PASS still does not qualify the compiled DLL's GPU behavior.
