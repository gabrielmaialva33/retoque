# NR Nexus x2 edit reuse versus Retoque model cadence

Date: 2026-11-19. Status: static comparison and proposed experiments; **no runtime
change or new GPU qualification**. Target for the proposals: RTX 3060 (sm86).
Retoque source: `22054268`, branch `nr/nr-reuse-20261119`, initially clean.
NR Nexus source: `a5a82ef917bbc0d18df6c39625804738d2d767ea` (v0.6.0 main merge),
local clone initially clean. Source was read locally; no binaries were executed.

This is a dated evidence/design record under [documentation authority](../../README.md),
not a replacement for [capabilities](../../capabilities.md), [NR rules](DEVELOPMENT.md)
or a recommendation to change installed game settings.

## Decision

**Retoque already reuses an edit and already skips a complete multi-pass chain.**
Nexus does not reveal a missing generic “run NR every second frame” optimization.
The useful differences are its log-ratio edit, bilinearly matched color confidence,
exact original-image selection, per-layer temporal processing, and a simpler x2-only
GPU path. They are experiments with image/route consequences, not safe CPU-only ports.

No candidate meets this task's phase-2 bar of clearly better, low-risk, host-testable
production work without shader regeneration. HLSL, shared shader-rule headers,
generated bytecode, settings and runtime code remain unchanged. Shader work belongs
to a later lead-owned build/validation step. No Nexus code was copied.

## What is reused and where it is applied

Let P be the current model proxy and A the fresh model answer. The following
equations describe the relevant domain, not interchangeable texture values.

| Dimension | Retoque at R1–R4 | Nexus at N1–N3 |
|---|---|---|
| Stored edit | Additive residual `R = A - P` in encoded model proxy space, plus proxy and depth snapshots. | Usually `E = log2(max(linear(A), 1/1024)) - log2(max(linear(P), 1/1024))`, plus linear reference and depth. Proxy/layer domains sRGB-decode first. |
| Reused answer | Current proxy plus accepted residual and rejected-region fill, bounded per channel to `[0,max(1,P)]`; ordinary final resolve still runs. | Current linear reference times `exp2(confidence * warped E)`; encode back for proxy domains. It is a multiplicative color edit, not an old output frame. |
| Spatial-only group | One final model-chain residual relative to the original untouched model input; a single final composition. | One `LINEAR_TERMINAL` anchor: log ratio of final decoded group color to original current color. Reuse skips the group and writes reconstructed decoded color. Even this mode stores an edit, not the previous final frame. |
| Temporal layer group | No equivalent per-layer Look stage. Each model has its own NGX history, while cadence stores one final-chain residual; output stabilization remains downstream. | Separate `LAYER_PROXY` anchors when a live per-layer Look stabilizer is active; each current layer input progresses through reuse/Look/resolve to the next layer, with no model Evaluate on a reuse frame. |
| Interval | Fixed 2, 3 or 4; optional conservative adaptive interval 1..configured maximum. | x2: refresh, one reuse, refresh. `valid`, `reused`, source sequence and contracts enforce this, rather than global frame parity. |
| Default | `Cadence=auto` resolves to 1; smoothing/adaptive/FG opt-in false. | `kEditReuse=false`; explicit existing Quality-page toggle. |

The difference is consequential at changing brightness: a linear gain naturally
scales with the current reference, whereas an encoded-space additive residual does
not generally do so. Retoque already scales its **fill** by a bounded luma ratio;
that does not turn its accepted residual into Nexus's log-ratio edit. Conversely,
Nexus's floor loses representability near black and its linear terminal path rejects
reference channels below that floor. Neither formula is universally superior.

“Adaptive” also names different things here: Retoque's cadence controller changes
the temporal interval from motion/rejection feedback (R5), while Nexus's Adaptive
worksets in this comparison are working-resolution tiers; its edit schedule remains
x2. Nexus's tier-selection fix is not a replacement for Retoque's motion policy.

## Reprojection, confidence and rejection

Retoque composes backward motion across all skipped frames in working pixels,
bilinearly samples the accumulated chain and validates the endpoint with depth/color.
A broken chain restarts from current motion. Before the next model Evaluate, invalid
history endpoints receive an off-screen vector, not a plausible old surface (R3).
Peripheral-compressed motion uses its already packed units (R2; [model cadence](model-cadence.md)).

Retoque's accepted residual is a clamped 16-tap Catmull-Rom sample. Acceptance is a
weighted nine-position neighborhood, gated by the center and an edge ramp. Each
position uses best-of-four depth at guide spacing and a **point-fetched** old proxy
color. Depth compares relative mismatch both in d and, for [0,1], in 1-d. Color
compares normalized chroma and relative luma with separate tolerances (R3:75–118,
322–377). On low acceptance it searches four rings of eight samples, retaining luma
fill only from matching surfaces; no match gives no fill. Present UI alpha suppresses
the carried edit. This is more work and a different quality tradeoff than Nexus.

Nexus reprojects directly to the one-frame-old anchor using current motion, with
explicit guide-raster/jitter offsets and Render anchor-raster delta (N2:96–119).
It bilinearly interpolates **both** the log edit and its reference with the same four
weights. Every nonzero-weight tap must have valid finite history and pass
`abs(depth_now-depth_then) <= 0.01 + 0.02*abs(depth_now)`. Out-of-frame, nonfinite,
dark-reference and failed-depth pixels are rejected. This raw depth tolerance is
not equivalent to Retoque's near/far-aware relative test; do not copy it alone.

Color confidence uses the weakest RGB channel of
`min(current, warped_reference) / max(current, warped_reference)`. A smoothstep gives
full confidence within 0.125 stop and zero at/above 0.375 stop maximum channel
difference; the **log edit** is multiplied by confidence (N2:140–147). Comparing the
warped reference, rather than each source tap to current color, avoids rejecting
correct subpixel high-contrast interpolation. It still cannot distinguish all
lighting changes from new surfaces, and has no nine-position or ring fill.

Nexus explicitly propagates per-pixel validity to `SELECT_ORIGINAL` **after decode**.
Invalid pixels get the exact current original float4; at lower working resolution
all nonzero contributors in the resolve's bilinear footprint must be valid
(N2:65–87). A valid neutral temporal layer preserves its current proxy without
invalidating the preceding layers' edits (N2:149–158). Retoque instead passes a
synthesized model-domain answer through its existing resolve/stabilizer; “zero
residual/no matching fill” is not the same contract as a post-resolve original
selection mask. Smoothing's global light limiter can also affect pixels with no fill.

## Histories, failure, passes and memory

Retoque records only after **every requested pass** succeeds; carry skips the primary
Evaluate and all extra Evaluates (R2:2827–2948,3174–3187). The chain supports up to ten
NGX instances at a shared working grid, each with independent model history
([bounded chain](bounded-chain.md)). It does not have Nexus's per-layer color transfer,
Look transport or mixed working-grid composition. Porting per-layer reuse without
those semantics adds memory and work without additional model-call savings.

Its scheduler forces refresh on reset, signature/feature/geometry/route changes,
gaps over 250 ms and duplicate calls in a counted present. The duplicate view's edit
is not saved. Scheduled refresh hands summed motion to **all** model passes; inability
to provide it resets their histories. Failed/partial work drops cadence history.
The signature covers model/per-pass settings and guide rules; final composition
controls can change without refresh because composition reruns every frame (R1/R2).

Nexus has up to four model slots (`dlssnr.hpp:314`) and uses per-feature/stage history
with a 40-word contract and source sequence.
It invalidates on a nonconsecutive sequence, contract/reset/geometry changes; retiring
after a skipped model frame also resets stale NGX/Look history. For spatial groups
it has one terminal anchor; temporal groups require all layer anchors to be valid
and the entire group to agree to reuse. Group effects include per-layer transfer,
color strength, grids and Look constants. Those affect the terminal edit and therefore
must invalidate it, unlike Retoque's post-edit composition controls (N3:13614–13924).

The next Nexus refresh composes current motion with the saved skipped frame's motion
on the guide grid, compensating raster offsets, and shares that read-only texture
across the group. Its motion shader does not perform Retoque's endpoint depth/color
validation; invalid previous lookup leaves the second motion zero and nonfinite
composition becomes zero (N2:41–63). Both designs address NGX history age; Nexus's
mechanism is specialized to one skipped frame. Failed delivery invalidates anchors,
and group reuse failure resets all relevant model/Look histories (N3:13910).

Nominal extra storage, excluding alignment, descriptors, models and existing outputs:
Retoque unsmoothed uses about `36*W*H + 8*ceil(W/16)*ceil(H/16)` bytes; smoothing adds
two RGBA16F working images and small light state. Nexus allocates
`36*W*H + 16*motionW*motionH` per prepared State (anchor, validity, saved/composed
motion). Terminal-group W/H are full output size; per-layer mode can allocate multiple
States even though only the first supplies shared motion. Therefore a simpler shader
does **not** imply less VRAM, especially with a reduced-resolution NR model (R4/N1).
Neither implementation's submission/retirement scheme should be transplanted: Retoque
already has tracked retirement/probe certificates and Nexus tracks State/bindings.

## What the reported gain means

N4 reports a **development candidate**, static Witcher 3 save, 4K Upscaled, FG off,
two A→B layers: 30.54 to 37.23 **base** FPS (+21.90%), 130 two-pass refreshes and 131
zero-Evaluate reuses, 261 completed writebacks and zero fallback. This is the project's
reported result, not independently reproduced here, not final-tag validation, not
RTX 3060 evidence and not generated/display FPS. N4 separately reports single-layer
native FG refresh/reuse evidence with incomplete capture and no end-to-end gain.

For planning only, let M be the sum of model times per refresh, B the other base-frame
work and H the *average incremental* reuse/history cost. Sustained x2 changes
`B + M` to approximately `B + M/2 + H`; modeled saved time is `M/2 - H`.
With carried fraction c below 1/2, it is `c*M - H`. This is an accounting model,
not a measured FPS forecast; synchronization, overlap, rejection and pacing matter.
The same model-call saving already exists in Retoque fixed C2. A replacement
algorithm at the **same** carry fraction can only save its difference in H, or improve
quality/acceptance. More model savings require increasing the actual eligible carry
fraction. WorkingScale changes M and must be fixed in any comparison.

The [deferred-coarse record](cadence-deferred-coarse.md) already warns that removing
work on model frames can increase first-carry cost and showed no net C2 win in its
single comparison. Its 4090 results must not be scaled into a 3060 prediction.

## Concrete gaps and proposed experiments

“Gain” below is the expected mechanism and its bound on sm86, **not measured time or FPS**.
No numeric 3060 prediction is justified by these sources.

| Priority / idea absent in this form | Expected gain on 3060 | Risk and implementation cost | Disposition |
|---|---|---|---|
| 1. Confidence against bilinearly warped reference, matched to edit footprint | May reduce false subpixel rejection and improve stable reuse acceptance. At fixed C2 saves no model calls; under adaptive scheduling any extra saving is `delta(c)*M`, only if its existing probe admits it. | Medium/high quality risk: Retoque samples Catmull-Rom edit and uses a neighborhood/depth policy; Nexus's bilinear test is not a drop-in equivalence. Change shared rule, probe expectations and shader bytecode; synthetic edges plus GPU motion corpus required. | Best bounded image experiment, **defer HLSL**. Do not simply loosen adaptive thresholds. |
| 2. Log-ratio edit in a clearly specified linear domain | Could follow brightness changes with less additive drift; may support reuse quality at the same c. No inherent model-time saving over current residual reuse. | High: near-black floor, negative/HDR channels, passthrough, proxy inversion and smoothing all need explicit semantics; log/exp work may cost more. New history format/math and bytecode, numerical + HDR tests. | Research candidate, not “clearly better”. |
| 3. Exact original selection for rejected pixels, matching final resolve footprint | Quality/failure containment; no additional skipped Evaluates. A simpler no-fill path might lower H but can reveal cadence-rate holes. | Medium/high: validity buffer, descriptors, ordering, final-resolution reconstruction, UI/stabilizer/limiter interaction. An extra full-resolution pass may erase savings. HLSL and lifetime integration required. | Compare no-fill/original-selection against existing ring fill before adopting. |
| 4. Specialized first/only carry at C2, fusing chain write and synthesis; Nexus also fuses apply with motion snapshot | Potential reduction in auxiliary dispatch/bandwidth cost H; cannot claim another 50% model saving. Most relevant if C2 is actually sustained. | Medium: first-carry current motion is sufficient, but chain must still be written for next model refresh; preserve coarse preparation, UI, smoothing and probe behavior. Shader/descriptor change; exact-output test if claiming arithmetic preservation. | Promising performance experiment after profiling; **defer HLSL**. |
| 5. Per-layer anchors with per-layer temporal postprocessing and/or mixed working grids | Enables semantics currently absent in Retoque; **zero extra model-call saving** for the existing shared-grid chain, which already skips all passes. | High and large: new layer processing architecture, separate histories, reset propagation, memory budget and output validity. Full-grid Nexus temporal restriction matters on a 3060 using reduced working scale. | Do not port merely to obtain multi-pass x2. |
| 6. Jitter-aware pre-upscale reuse with explicit raster identity | Could enable `c*M-H` savings on a currently refused route. No benefit on already eligible after-upscale routes. | High: downstream SR accumulates errors; guide provenance, raster delta, reset and source sequence contract plus new GPU fixtures required. | Separate route design; keep current refusal. |
| 7. Request/effective/delivered reuse counters with rejection categories | No direct GPU gain; makes missed reuse diagnosable and separates model skips from original-image fallback. Existing status/GPU timing/funnel already cover part of it. | Low/medium, CPU-testable, but “delivered” must come from completion evidence, not recording success; counter ownership/readback/diagnostic design is still needed. | Useful follow-up, not an assumed performance fix or trivial counter port. |

Not missing: whole-chain skipping, backward motion composition for NGX history,
reset preservation, depth/color rejection, default-off behavior, fallback reasons,
or adaptive admission. No new setting or control is proposed here. Any later accepted
implementation must stay behind the existing cadence gates and leave `Cadence=1`
and NR-off behavior unchanged; the experiment must not silently redefine smoothing.

## Validation and next acceptance boundary

This review ran existing host suites `nr-cadence` and `nr-multipass`, serially inside
a 6 GiB memory/1 GiB swap scope: **2 PASS, no skips**. These execute portable production
rules/source guards; they do not execute Nexus or compile either shader. The separate
worker report records exact commands, logs and final documentation checks. No new
test was added because production behavior was not changed.

For a later shader experiment, freeze current C1/C2 and adaptive behavior at equal
model, pass count, working scale, HDR and FG settings. Check default-off output and
decisions, reset at a skipped frame, partial chain failure, duplicate view, dimension
change, jitter/subpixel high-contrast edges, disocclusion, moving lights, dark/negative/
nonfinite channels, UI and original-selection footprints. Include cut/recovery,
source/queue generation changes and bounded in-flight ownership. Preserve rejected
temporal experiments in [module notes](../../../retoque/dlssnr/README.md) and
[cadence smoothing](cadence-smoothing.md).

The lead must regenerate the affected D3D12 cadence bytecode (and both DXIL/SPIR-V
if touching the common NR shader), build under the shared compiler lock, then verify
same-input GPU output, completion, host and native Windows D3D12 behavior. Only a
separate 3060 game study can establish auxiliary cost, carried fraction, base-frame
timing and FG pacing. No GPU, Wine, MSVC, dxc, DLL build, installation or game test was
performed in this review.

If a later implementation copies Nexus code, retain its MIT source notices and add
the license under `Licenses/` plus the repository's third-party attribution entry.
Nexus root `LICENSE` names Copyright (c) 2025 Carlos Lopez Jr.; the examined reuse
files also carry their 2026 MIT headers. This prose-only comparison imports no code
and therefore adds no vendored-source notice.
